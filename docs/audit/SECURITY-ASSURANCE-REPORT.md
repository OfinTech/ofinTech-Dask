### OB-01 · OAuth callback trusted a prefix-matched Zoho host — P1
1. `connectors/flows.py` accepted any `accounts-server` starting with `https://accounts.zoho` and any `api_domain`.
2. Local probe: callback with a valid state and `accounts-server=https://accounts.zoho.attacker.test` → a token request, carrying the code and client secret, was sent to the attacker host.
3. Exact match against Zoho's data-centre and API-host lists (769e263).
4. `OB01ZohoCallback.test_lookalike_accounts_server_gets_no_token_request` (4 hosts → 400, no request), `…test_api_domain…`.
5. `test_more.ZohoFlow` (genuine EU callback completes, datasets sync) — pre-audit test, unchanged.
6. Pre-audit suite; golden (no financial path).
7. Both fail on the old code, pass now; CI green.
8. Needs a valid unused OAuth state to exploit; none left. **CLOSED**

## 3. Adversarial testing performed

`test_adversarial` (13) and `test_isolation` (6) and `test_ai_security` (13) and `test_backup` (5) cover the
gate's list: cross-tenant access (rows, objects, retrieval, memory, conversations, MCP keys, background jobs,
exports, audit), privilege escalation (viewer × 6 operations, invitation reuse, oversight), prompt injection (user
text, document, spreadsheet, upstream error page, unoffered and nonexistent tools), MCP abuse (payment
laundering, changed tool, write tool never unattended), malicious documents (zip bombs across six readers,
EPS-as-image, hostile pixel headers, formula prefixes incl. invisible characters), webhook and connector
manipulation (look-alike OAuth hosts, chunked bodies, credential leakage in payloads), authentication and session
attacks (tampered/revoked/idle/query tokens, forged origins), leakage through logs, errors and exports (canary
secrets in failed logins, forgot-password and a failing connector; CSV export of one workspace), backup theft and
unauthorised restoration (ciphertext opaque; master key useless; tampering refused; overwrite refused), concurrency
(two turns on one thread; two decisions on one approval; a half-failed import).

Attacks that succeeded during the work and are now closed: invisible prefix before `=` in exports; credentials under
unlisted key names in webhook payloads; a departed creator's workflow still acting; the oversight desk visible to
viewers; the masker eating document ids. Each has a test.

## 4. Financial integrity

- Golden fixture from the pre-audit engine: identical at every commit of the audit.
- Oracles: NPV/IRR, loan schedule (total paid = principal + interest, last payment absorbs rounding), depreciation ×3, tax splits, break-even, CAGR, FX, ratios, variance signs, Excel rounding, sums by month/fiscal year/account, journal balance and dates: 11/11.
- Date and currency determinism: fiscal-year grouping and month buckets computed in SQL from the workspace's start month; currency is a label the engine never converts without a user-supplied rate (`calc_currency_convert` states the rate and date).
- Reproducibility: generated workbooks resolve every cell from dataset queries and thread evidence; literal figures without evidence are marked `unverified`; the reviewer runs with a fresh context (`test_files`, `test_ai_security` cases 10–12).
- The LLM cannot modify authoritative calculations: formulas are parsed by the engine (no code path, `test_ai_security` case 10), tool results are computed in code, tool arguments are schema-checked, and the figure check lists numbers that appear in no source.
- Data migrations: none added; a pre-audit data directory opens unchanged; backups restore with the same sums.

## 5. Performance impact

Suite 20 s → 28 s with 87 more tests (incl. 10 upstream). The request-time network guard costs one DNS lookup per
host per minute on servers. Dataset work off the loop improved responsiveness (benchmark in §2 DB-02). No other
change touches a hot path.

## 7. Production deployment risks

1. Run `storage-encrypt` once where files predate encryption (or set the flag temporarily).
2. Generate `backup.key`, keep it apart from the server and from the master key, schedule `backup.sh` and `backup-check`.
3. List internal model/PipesHub hosts in `DESK_EGRESS_ALLOW` or run sealed.
4. MCP tools previously set to run unattended ask once until re-saved; Gmail/Drive imports and file edits now ask.
5. Pin the Trivy image and the actions by digest when a maintainer can resolve them.
6. Validate each live integration the customer will use before go-live.
